# 像素打卡

面向 FoloToy AI Passport（ESP32-C3）的离线像素风打卡应用。六个每日习惯、三个按键、
不联网、不需要账号、也没有手机端；打卡记录在掉电后依然保留。

这是一个 fork 内的独立应用：界面按板子的 BSP 与例程重新设计，没有复用基线 demo 的
测试菜单和视觉外壳，也没有改动上游的硬件层。界面文案为简体中文。

## 打卡模型

| 项目 | 行为 |
| --- | --- |
| 类别 | 早睡、锻炼、戒烟、喝水、阅读、早起 |
| 打卡 | 每个逻辑日每项一次；重复打卡被拒绝，而不是覆盖 |
| 记录 | 90 个环形槽位，按 `day % 90` 定位；每槽自带日期与 6 位掩码 |
| 连续天数 | 单项连续打卡天数，从今天往回数；当天尚未结束不算中断 |
| 日界 | 凌晨 04:00，因此 03:59 的打卡属于前一天 |
| 存储 | NVS，逐字段小端序，带 magic、版本、槽数与长度校验；任何一项不符都按"无记录"处理，不猜 |

类别的顺序是存储格式的一部分：每一项的位序就是它在当天掩码里的 bit 位置。所以新增
类别只能追加 —— 六项共用 1 字节，原先三项仍占据它们一直占用的低位，早期固件写下的
记录因此仍指向同样的类别。这个格式的上限是 8 项，超出会被 `_Static_assert` 变成构建
错误，而不是悄悄改变格式。

## 按键操作

| 按键 | 主菜单 | 打卡确认页 | 结果页 | 月历页 | 日期页 |
| --- | --- | --- | --- | --- | --- |
| 上 / 下 短按 | 切换类别 | — | — | 上一月 / 下一月 | 调整当前高亮字段 |
| 确定 短按 | 进入打卡确认页 | 打卡 | 3 秒内撤销这次打卡，否则返回主菜单 | 切换下一个类别 | 下一段，最后一段确认日期 |
| 确定 长按 | 进入月历页 | 返回主菜单 | 保留这次打卡并返回 | 返回主菜单 | 返回（首次设置时不允许取消） |
| 熄屏时按任意键 | 点亮屏幕；这一次按下被吞掉，不传给界面 | | | | |

主菜单一屏显示三行，靠窗口在类别列表上滚动，所以屏幕上的对象数量固定，不随类别数增长。
顶栏下方一行左边是今日完成度（2/6），右边是选中类别的连续天数；选中项到首尾会环绕，而
窗口本身在列表两端停住，因此不会出现空行。

## 误打卡撤销

打卡只隔一次按键就会发生，所以成功页同时充当三秒撤销窗口：页面还在时按确定会撤回今天
这一项的打卡并回到主菜单，长按确定则是保留这次打卡并返回。窗口只给一次，而且撤销也会
落盘 —— 否则重启后那次打卡又回来了。

撤销刻意不出声。反馈交给可见的结果：卡片上的实心标记消失，今日完成度减少一格。用上行
提示音会让人以为"又完成了一次"，正好相反。撤销提示只出现在真的可以撤销的页面上，
"今天已打卡"那一页因此不会邀请用户去按一个什么也不会发生的键。

## 月历页

长按确定进入月历，一次只看一个类别：顶部是年月，其下左侧是类别名、右侧是它的连续天数，
再往下是七列网格，每格一天并带日期数字。已打卡的格子整格填绿，今天用黄色描边标出，
非本月的格子直接隐藏。按确定依次切换六个类别。

网格固定为七列六行 —— 这是能装下任何月份的最小固定形状：31 天且 1 号是周日的月份要占
37 格。因此换月或换项只是改写已有的 42 个格子，不重建页面。

两端是停住而不是环绕：最新的月份就是当月，最旧的是 `今天 - 89` 所在月，这来自 90 个环形
槽位。更早的日期已经不在存储里，再往前翻只会看到一片空网格，反而像记录丢了。全新设备上
连续天数位置显示"暂无记录"，而不是"连续0天"。

打卡成功时结果卡片变绿并播放两声上行方波提示音；重复打卡播放一声低音且不写 Flash。
NVS 写入失败会在界面上报错并配低音 —— 记录丢失不会静默发生。

## 没有时钟源时的日期

板子既没有联网，也没有 32.768kHz 晶振，没有任何绝对时间来源。日期由用户设定一次，
之后由应用用 RTC 计数自己往前走：该计数在深睡与普通复位后连续，只有掉电才归零。

RTC 保留内存里存有一个时间锚点，用来判断"日期是否还可信"：它跨深睡与复位有效，掉电即
失效。锚点丢失时应用不会假装知道日期，而是先请用户确认或修正，再进入主菜单。最后一次
已知墙钟也会写进 NVS，所以确认时看到的是大致正确的日期，而不是一个固定默认值。

## 省电

空闲时间从最后一次按键起算，分两级：

- 15 秒后关背光。MCU 仍然运行，所以下一次按键立刻恢复画面，不必付出一次重启的代价。
- 30 秒后进入深睡。入睡前依次：装好唤醒源、停掉提示音任务、冻结输入、刷写最后已知日期，
  然后按 CW2017 电量计 → ES8311 codec → I2S 引脚 → 共享 I2C → 面板的顺序关机。

三个键都能唤醒：它们共用一个带外部上拉的 ADC 节点，任意一键都把这个节点拉低。ESP32-C3
没有 EXT0/EXT1 唤醒，固件改用 GPIO 低电平唤醒，并且把"唤醒源没装上"当成不睡的理由 ——
没有唤醒源就睡下去，设备只能靠断电重启才能恢复。

深睡唤醒会重启应用：日期由 RTC 锚点推出所以保持连续，而唤醒来电的那一次按下被刻意不交给
界面，避免"叫醒屏幕"顺手改掉选中项。

## 使用到的硬件

| 器件 | 接口 | 用途 |
| --- | --- | --- |
| ST7789P3 240 × 320 | SPI2 + LEDC 背光 | 唯一的用户界面 |
| ES8311 | 共享 I2C + I2S0 | 两声打卡提示音 |
| CW2017 | 共享 I2C，地址 `0x63` | 顶栏电量百分比（读不到时隐藏该项） |
| 三键分压 | GPIO0 上的 ADC1 通道 0 | 选择、打卡、返回，以及深睡唤醒 |

引脚号、电压窗口与寄存器细节属于
[`components/bsp/include/bsp_pins.h`](../../components/bsp/include/bsp_pins.h)
与[硬件开发指南](../hardware-design/AI_HARDWARE_DEVELOPMENT_GUIDE.zh_CN.md)；应用自身不含
任何引脚常量。

## 源码结构

| 文件 | 职责 |
| --- | --- |
| `main/main.c` | 极简入口 |
| `main/habit_app.c` | 事件任务、NVS 写入、墙钟基准、空闲计时、深睡序列 |
| `main/habit_ui.c` | 五个像素页面，含滚动菜单与整月网格 |
| `main/habit_strings.h` | 界面文案的唯一来源 |
| `main/habit_audio.c` | 独立任务上的提示音，以及入睡前的挂起握手 |
| `main/habit_device.c` | 唯一接触 RTC 计数、RTC 保留内存与 NVS 的文件 |
| `main/habit_date.c`、`habit_model.c`、`habit_clock.c`、`habit_store.c` | 纯 C 逻辑与编码，带主机测试；月历翻页用的月游标在 `habit_date.c` |

并发被刻意收窄：按键与定时器回调只入队，界面、记录与每一次存储写入都由同一个任务负责。

## 构建、烧录与测试

```bash
source $IDF_PATH/export.sh
./tools/validate.sh --static     # 仓库检查 + 主机测试
./tools/validate.sh --firmware   # ESP-IDF 构建 + 合并镜像校验
./tools/validate.sh              # 两者
```

`tools/validate.sh` 在临时目录里构建，并安装 `build/FoloToy-AI-Passport-full.bin` —— 从
偏移 `0x0` 写入的合并镜像。烧它会清空 NVS。想保留已存的记录与日期锚点，就只烧应用分区，
应用镜像在调试归档里：

```bash
python -m esptool --chip esp32c3 -p <port> -b 460800 --before default_reset \
  --after hard_reset write_flash --flash_mode dio --flash_size 8MB --flash_freq 80m \
  0x10000 build/firmware/<image-sha256>/FoloToy-AI-Passport.bin
```

通过 USB Serial/JTAG 看日志时有两个事实要注意：芯片深睡期间串口节点会消失；一次启动的
头几行可能在接口枚举完成前被丢掉。应用把唤醒原因放在「就绪」日志里而不是 `app_main` 的
第一行，就是因为这一点。

## 字体

界面使用 Ark Pixel（OFL-1.1 许可），12px 与 24px 两档。文案只存在于
`main/habit_strings.h`，字形子集由该文件派生。因此**改动任何界面文案都必须重新生成字体**，
步骤与 `lv_font_conv` 的完整参数见 [`assets/README.md`](../../assets/README.zh_CN.md)。
主机测试 `tests/test_app_font_coverage.py` 会让这条约定无法被绕过：它从文案头文件提取汉字
清单，只要字符清单或两个子集没有覆盖界面会打印的每一个字就会失败。

## 验证状态

真机已观察到：简体中文点阵字渲染正常；最后一次按键约 30 秒后进入深睡（串口消失）；任意键
可唤醒，连续两次成功，唤醒后日期仍然可信。

真机尚未确认：15 秒熄屏（只能目视、不留日志）、重复打卡拦截、提示音，以及「就绪」日志里的
唤醒原因数值。

六项版本还没有在任何真机上跑过。具体未验证：三行滚动窗口在列表两端的停位与环绕、今日计数
与连续天数是否随选中项更新，以及"三项目固件写下的记录在只烧应用分区后仍能正确读回"这条
升级路径。

月历页同样未上机：五行的月份与六行的月份里星期列是否都对齐真实日期、今天的描边、两端换月
的夹取、类别循环，以及一屏 42 个格子加 42 个标签在按键时会不会出现可见延迟。

撤销窗口也未上机：三秒内撤销后确认重启仍然没有那次打卡、等窗口过期后打卡保留、以及窗口
期内长按确定不会丢掉这次打卡。
